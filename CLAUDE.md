# CLAUDE.md

## Agent contract

rdsh's primary consumer is an AI coding agent calling it from a shell; the conventions below exist to keep that contract stable.

- **Three-way documentation sync** — user-facing CLI behaviour is stated in `README.md`, `skills/rdsh/SKILL.md`, and the cobra help strings under `internal/cmd/`. Changing the CLI means updating all three in the same PR. Overlaps today: the 90 s default `--timeout`, the exit codes, and the default output format.
- **The plugin description is a synced surface** — the one-line description in `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` (top level and the `plugins[]` entry) and `.goreleaser.yaml` (the `homebrew_casks` entry's `description`, which is what `brew info` shows) must be byte-identical, and must say the same thing as the repository's GitHub "About" text and the README's opening line. Clients resolve two of these copies at different refs — the marketplace catalog from the default branch, the plugin manifest from `stable` — so they legitimately differ between a description edit landing on main and the next release; edit all four together and the release converges them.
- **Output format and exit codes are a contract** — stdout format (CSV/TSV/JSON) and the exit codes produced by `exitCode` in `internal/cmd/root.go` (`0`, `124` on timeout following the GNU `timeout` convention, `1` for everything else) are branched on mechanically by agent consumers. Changing either is a breaking change, held to a higher bar than for a human-facing CLI. The JSON spelling is held by `outputOptions` in `internal/format/format.go` and the explicit newline beside it: `EscapeForHTML`, `EscapeForJS`, `PreserveRawStrings` and `Deterministic` are each load-bearing, and none of them is what `encoding/json/v2` does on its own — dropping any as redundant changes the bytes. Result rows are normalised to match on the way in, by `cellOptions` in `internal/redash/redash.go`. `internal/format/options_test.go` fails if one goes missing.
- **`stable` is moved only by the release workflow** — the `plugins[]` entry in `.claude-plugin/marketplace.json` resolves through the `stable` tag, `README.md`'s `npx skills` install command names it in the URL form, and `.github/workflows/release.yml` force-pushes it onto the new tag once the archives are published and attested. Moving it by hand ships content without changing the `version` in the manifest, and Claude Code keeps the copy it has cached, so updates stop silently. Shortening that install command to the `178inaba/rdsh@stable` shorthand unpins it just as quietly, in the other direction: the shorthand resolves `stable` at install time but records no ref, so the next `npx skills update` falls back to the default branch and the skill runs ahead of the released binary it describes. `.github/workflows/ci.yml` asserts the URL form for that reason. The exception is a release that got as far as attesting the archives and then failed on that last push: re-running the job moves nothing, since tagpr emits no tag once one exists, and the tagged tree already carries the bumped `version` — force-pushing `stable` onto that release's tag by hand is the repair.
- **The plugin's `version` lives in `.claude-plugin/plugin.json` only** — never on the `marketplace.json` entry. Claude Code always takes the manifest's value without warning, so a version in both places lets a stale manifest mask the other one. Keeping it in the manifest also puts it inside the tree `stable` points at, so the version a plugin advertises and the content it serves cannot disagree. tagpr bumps it through `versionFile` in `.tagpr`.
- **No unrequested execution** — a command executes the caller's SQL only where the caller asked for it. `rdsh run` and `rdsh query refresh` are that ask; every other command reads. This is why `visualization create` refuses a query whose page holds no result rather than producing one: executing spends time on someone else's warehouse and advances what colleagues see on the query page — neither of which a command named for adding a chart was asked to do. A flag the caller passes counts as asking, so a command may execute under an explicit one — what this rules out is executing as a side effect of a command that reads. Refusals name `rdsh query refresh` so the caller can choose to pay.
- **`scripts/redash-seed.sql` and the e2e assertions move together** — the suite under `e2e/` (build tag `e2e`) drives the built binary against the sandbox `scripts/redash-up.sh` brings up, and asserts on the seed's own values: row counts and the date range. It can, because the rows are generated deterministically, so an assertion only breaks when the seed is changed on purpose — and then both are fixed in the same PR. What the suite covers is only what an in-process fake can be wrong about; rdsh's own behaviour stays with the fake tests.
- **`skills/rdsh/SKILL.md` is router-style** — activation conditions and workflow only; per-command syntax stays delegated to `rdsh --help`. This was settled in 178inaba/rdsh#2, and per-command detail has already drifted back in once.

## Code conventions

Shared across the sibling CLIs (cflio, rdsh, slio):

- cobra commands are wired constructor-style (`newXCmd()` returning `*cobra.Command`); no package-level command or flag variables.
- Output formatting lives in `internal/format`. An API-client package is named after the service, and its main file after the package.
